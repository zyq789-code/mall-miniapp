# 商城购物小程序（uni-app）

面向求职展示的专业级商城购物小程序，覆盖从选品、下单、支付到售后的完整电商闭环，并包含营销玩法与会员体系。业务核心全部以纯函数实现并通过单元测试保障，可作为 Web 前端 / 直播电商方向的工程能力参考。

## 项目亮点

- **清晰的分层架构**：`pages → stores → services → api` 单向依赖，页面只负责渲染与交互，业务规则统一收敛在 services 层。
- **纯函数业务核心**：购物车、优惠券、订单状态机、积分、秒杀、售后流转等均实现为无副作用的纯函数，全部可单测，逻辑即文档。
- **设计令牌统一视觉**：`uni.scss` 集中定义品牌色、价格色、文本层级、圆角等设计令牌，全局视觉一致、易于主题化。

## 功能清单

### 基础购物

- 首页：Banner 轮播、商品推荐流
- 分类：两级分类导航
- 搜索：按关键词模糊检索商品
- 商品详情：SKU 规格选择、库存与多规格价格切换
- 购物车：增减数量、勾选 / 全选、批量删除、金额实时计算
- 下单：确认订单、优惠分摊、运费计算
- 模拟支付：收银台与完整支付流程
- 订单管理：订单列表 / 详情，付款、取消、发货、收货状态流转
- 收货地址：地址列表、新增 / 编辑、默认地址

### 营销玩法

- 优惠券：领券中心、我的优惠券、满减 / 折扣券可用性校验、自动匹配最优券
- 秒杀：场次判断、限购校验、扣减库存、秒杀价计算
- 限时折扣：折扣价换算与活动时间判断

### 会员用户

- 模拟登录：昵称 + 头像本地登录
- 会员等级：按累计消费自动升级，不同等级对应不同返积分倍率
- 积分：消费得积分、积分抵现（上限比例控制）
- 每日签到：跨天签到判定
- 我的收藏、浏览足迹

### 交易增强

- 售后流转：申请、审核、退款、驳回、重新申诉
- 物流跟踪：订单物流信息
- 评价：仅已完成订单可评价，评分与内容长度校验

## 架构说明

```text
pages（页面 / 组件，只负责渲染与交互）
   │
   ▼
stores（Pinia 状态 + 本地持久化，编排服务调用）
   │
   ▼
services（纯函数业务规则，无平台依赖，可单测）
   │
   ▼
api（数据访问抽象：本地 storage 持久化 / mock 仓库）
   │
   ▼
mock（商品、优惠券、秒杀等模拟数据）
```

**为什么 services 是纯函数？**

- 金额计算、优惠匹配、订单状态机、库存 / 限购校验、售后流转等规则全部收敛在 `src/services`，输入输出明确、无副作用，规则变更只改一处。
- 纯函数不依赖 uni-app 运行时，Vitest 在 Node 环境即可直接测试，无需 mock 平台 API，这也是 59 个单测可以稳定快速运行的原因。
- 数据访问被 `api` 层隔离：当前使用本地 storage + mock 仓库，未来接入真实后端只需重写 `api` 层，`services` 与页面零改动。

## 如何运行（全栈）

项目分三部分：**后端 API**（Express+SQLite）、**管理后台**（React+AntD）、**小程序/H5**（uni-app）。

```bash
# ① 后端 API（端口 3000）
cd server && npm i && npm run dev

# ② 管理后台（端口 5173，浏览器打开 http://localhost:5173，账号 admin/admin123）
cd admin && npm i && npm run dev

# ③ 小程序/H5（根目录）
npm i
npm run dev:h5        # H5 预览（商品/订单从后端取数）
npm run test          # 运行单元测试（59 tests）
npm run dev:mp-weixin # 微信开发者工具预览
```

> 小程序商品/订单数据由后端提供；管理后台增删商品/上下架/发货，小程序实时可见。

## 部署

- **H5 在线预览（Vercel，国际访问）**：`https://mall-miniapp.vercel.app`（此为全 mock 版本；全栈版需后端配合）
- **微信小程序体验版**：appid 已配置，通过微信开发者工具上传 → 设为体验版 → 生成二维码。
- **全栈部署说明**：商品/订单已接真后端。体验版/线上版要显示服务器数据，后端需部署到公网 HTTPS 地址（微信要求 request 合法域名 + HTTPS + 备案），并在 `src/utils/config.ts` 改 `API_BASE_URL`。国内开发调试可在开发者工具勾选"不校验合法域名"用 `http://localhost:3000`。

## 目录结构

```text
src/
├─ api/          # 数据访问抽象（storage 持久化、仓库接口）
├─ components/ui # 通用 UI 组件（SkuPopup、GoodsCard、PriceTag、Stepper 等）
├─ mock/         # 模拟数据（商品、优惠券、秒杀）
├─ models/       # 领域模型（商品、订单、优惠券、会员、售后等）
├─ pages/        # 页面（首页 / 分类 / 购物车 / 订单 / 会员 / 售后…）
├─ services/     # 纯函数业务规则（单测核心）
├─ stores/       # Pinia 状态（cart / order / user）
├─ utils/        # 通用工具（格式化、业务错误、storage、toast）
├─ uni.scss      # SCSS 设计令牌
├─ pages.json    # 页面路由与 tabBar 配置
└─ manifest.json # 应用配置（多端发行）
```

## 测试

- 共 **59 个单元测试**，覆盖 `src/services` 与 `src/utils` 全部模块。
- 覆盖率：**services + utils 行覆盖率 99%**（199/201），函数覆盖率 98%。
- 测试均为纯逻辑断言（Vitest + Node 环境），无平台 mock 依赖，运行快、结果稳定。
